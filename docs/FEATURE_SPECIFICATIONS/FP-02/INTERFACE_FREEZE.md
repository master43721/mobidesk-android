## 1. Scope and Boundary Definition

This document freezes the interfaces and contract primitives shared across:
- **FP-01 (Authentication & Recovery)**
- **FP-02 (Student Dashboard & Workspace Shell)**
- **FP-03 (Assignment Resolution)**
- **FP-04 (VM Lifecycle & Readiness Status Client)**
- **FP-05 (Credential Prompt & Handoff Preparation)**

Server-side assignment resolution (FP-03) and the VM status probe endpoint (FP-04) reside in the external `session-broker` repository. The Android client implements the client interfaces defined herein against `docs/API_CONTRACT.md`.

## 2. Core Frozen Interfaces & Types

### 2.1 AuthLevel Gate (FP-01 Boundary)

Protected student data requests (workspace profile, assignment resolution, VM status) MUST be gated strictly by `AuthLevel`:

```kotlin
enum class AuthLevel {
    SIGNED_OUT,
    RECOVERY_ONLY,
    FULLY_AUTHENTICATED
}
```

- **Invariant:** When `authLevel != FULLY_AUTHENTICATED`, no protected request may be issued.
- **Invariant:** Recovery sessions (`RECOVERY_ONLY`) must never load workspace data or probe VM status.

---

### 2.2 Injectable Monotonic Clock

To ensure testability and prevent reliance on user/device wall-clock tampering:

```kotlin
interface MonotonicClock {
    fun elapsedRealtime(): Long
}

object SystemMonotonicClock : MonotonicClock {
    override fun elapsedRealtime(): Long = SystemClock.elapsedRealtime()
}
```

- **Invariant:** Handset wall clock (`System.currentTimeMillis()`, `Date`, RFC 3339 string parsing against device time) MUST NEVER be used to evaluate sample freshness.
- **Invariant:** Freshness uses elapsed monotonic milliseconds captured at request dispatch (`requestStartedElapsedMs`) and response receipt (`responseReceivedElapsedMs`).
- **Age Upper-Bound Formula:**
  $$\text{ageUpperBoundMs} = (\text{responseReceivedElapsedMs} - \text{requestStartedElapsedMs}) + (\text{nowElapsedMs} - \text{responseReceivedElapsedMs})$$
- A sample is fresh iff $\text{ageUpperBoundMs} < \text{staleAfterSeconds} \times 1000\text{ ms}$.

### 2.3 Assignment Repository & Presentation (FP-03 Boundary)

```kotlin
interface WorkspaceRepository {
    suspend fun loadFor(userId: String): StudentWorkspaceResult
}

data class StudentProfile(
    val id: String,
    val name: String,
    val college: String
)

data class AssignedWorkspace(
    val displayLabel: String,
    val assignmentTag: String
)

sealed interface StudentWorkspaceResult {
    data object AccountNotProvisioned : StudentWorkspaceResult
    data class NoAssignment(val profile: StudentProfile) : StudentWorkspaceResult
    data class AssignmentInvalid(val profile: StudentProfile, val reason: String) : StudentWorkspaceResult
    data class Assigned(val profile: StudentProfile, val assignedWorkspace: AssignedWorkspace) : StudentWorkspaceResult
}
```

- **Exactly-One Rule:** Exactly one valid assignment must resolve. Zero assignments (`NoAssignment`) or multiple/inactive assignments (`AssignmentInvalid`) fail closed.
- **Privacy Invariant:** Requests and presentation data MUST NEVER send or display `vm_id`, internal hostname, private IP address, or raw port (3389).
- **Correlation Invariant:** `assignmentTag` is an opaque equality-only token generated by the server resolver. It is never displayed to the student.

### 2.4 Status Repository & Snapshot (FP-04 Boundary)

```kotlin
interface StatusRepository {
    suspend fun getVmStatus(accessToken: String): StatusResult
}

enum class VmLifecycle {
    STOPPED, STARTING, RUNNING, STOPPING, ERROR, UNKNOWN;
    val isKnownNegative: Boolean get() = this in listOf(STOPPED, STARTING, STOPPING, ERROR)
}

enum class RdpTransport {
    NOT_CHECKED, TCP_UNREACHABLE, TCP_REACHABLE, RDP_NEGOTIATION_OK, UNKNOWN;
    val isKnownNegative: Boolean get() = this in listOf(TCP_UNREACHABLE, TCP_REACHABLE)
}

data class VmStatusSample(
    val lifecycle: VmLifecycle,
    val rdpTransport: RdpTransport,
    val sampledAtFormatted: String?,
    val probeDurationMs: Long,
    val staleAfterSeconds: Long,
    val requestId: String?,
    val assignmentTag: String,
    val requestStartedElapsedMs: Long,
    val responseReceivedElapsedMs: Long
)

sealed interface StatusResult {
    data class Success(val sample: VmStatusSample) : StatusResult
    data class RateLimited(val retryAfterSeconds: Long, val message: String) : StatusResult
    data class AuthExpired(val message: String) : StatusResult
    data class Error(val message: String, val isTransient: Boolean) : StatusResult
}
```

- **Fail-Closed Stream Reading:** `readBounded` enforces a strict 65,536-byte limit on responses. Exceeding this limit throws `ProtocolException` and fails closed to `StatusResult.Error`.
- **Rate-Limiting (HTTP 429):** Reads `Retry-After` header and optional body metadata. Delay defaults to $\ge 2\text{ s}$. Error message strictly adheres to catalogue copy `ASSIGN-02`. Arbitrary server error copy is NEVER shown to the student.
- **Client Timeout:** 8,000 ms connect and read timeout (comfortably above the 1,500 ms broker probe budget).

### 2.5 Error Catalogue Taxonomy (PRD v1.2 §12)

| Code | Trigger Condition | Canonical User Copy |
|:---|:---|:---|
| `AUTH-01` | Session token expired (HTTP 401) | *"Your sign-in session expired. Sign in again."* |
| `ASSIGN-01` | Account not provisioned or no VM assigned | *"No Cloud PC is assigned to your account. Contact the lab administrator."* |
| `ASSIGN-02` | Status read failure, timeout, oversized stream, or rate limit | *"We could not verify your assigned Cloud PC. Try again."* |
| `ASSIGN-03` | Assignment-to-status tag mismatch after retry | *"Your Cloud PC assignment needs administrator review."* |
| `VM-01` | VM is powered off (STOPPED) | *"Your Cloud PC is powered off. Contact the lab administrator."* |
| `VM-02` | VM is starting or stopping | *"Your Cloud PC is starting or is not ready yet."* |
| `VM-03` | RDP service unreachable (TCP_UNREACHABLE) | *"Your Cloud PC cannot be reached right now."* |

### 2.6 Connect Gate Policy (AMD-01 Approved Specification)

```kotlin
object ConnectPolicy {
    fun isConnectAvailable(
        authLevel: AuthLevel,
        isAssigned: Boolean,
        sample: VmStatusSample?,
        nowElapsedMs: Long,
        isRequestInFlight: Boolean,
        isCooldownActive: Boolean
    ): Boolean

    fun isHandoffEligible(
        authLevel: AuthLevel,
        isAssigned: Boolean,
        currentAssignmentTag: String?,
        sample: VmStatusSample?,
        nowElapsedMs: Long
    ): Boolean
}
```

- **Button Availability:** Connect is available when the student is assigned, auth is `FULLY_AUTHENTICATED`, and no fresh negative status is active. A stale or absent sample leaves Connect available to initiate a fresh status probe.
- **Handoff Invariant:** No handoff to FP-05 may occur from stale, cached, or mismatched state. Handoff strictly requires a fresh probe returning `RUNNING` + `RDP_NEGOTIATION_OK` and an identical `assignmentTag`.
