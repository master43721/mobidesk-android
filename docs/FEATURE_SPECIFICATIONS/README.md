**Canonical repository:** master43721/mobidesk-android  
**Status:** Feature packages are developed and reviewed one at a time. A draft package is not implementation approval.

## Packages

| Feature | Name | Status |
|---|---|---|
| [FP-01](FP-01/README.md) | Student Authentication and Account Recovery | Owner-directed implementation handoff; provider/device release gates remain open |
| [FP-02](FP-02/README.md) | Student Dashboard and Workspace | Draft v0.1 — Owner review required; FP-01/03/04 contracts are dependencies |

## Package lifecycle

1. Create a source-grounded v0.1 package with PRD, design, plan, tests, security, decisions and open questions.
2. Owner critiques the draft and selects KEEP / CHANGE / REMOVE / ADD.
3. Reconcile all documents together and check source/requirement/test traceability.
4. Publish v1.0 for approval.
5. Decompose the approved specification into implementation tasks.
6. Implement in small code changes and record reproducible evidence in the feature progress log.

Do not start coding from an unreviewed v0.1 package unless the Owner explicitly authorizes a specific spike.
